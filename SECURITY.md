# Security Policy

## Supported Versions

Only the latest major release receives security updates. Please upgrade to the newest version before reporting an issue.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.0 (live deployed as of Nov 12th)   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

Instead, report them privately using the [Report a vulnerability](../../security/advisories/new) button under this repository's **Security** tab. Only the maintainers can see these reports.

Please include as much of the following as you can:

- A description of the vulnerability and its potential impact
- Steps to reproduce, or a proof of concept
- Affected version(s), commit, or configuration
- Any suggested fix or mitigation

## What to Expect

- **Acknowledgement:** within 3 business days of your report.
- **Status updates:** at least every 7 days while the issue is being investigated.
- **If accepted:** we will work on a fix, coordinate a release date with you, and publish a security advisory. With your permission, we will credit you for the discovery.
- **If declined:** we will explain why we don't consider it a vulnerability or why it is out of scope.

Please give us a reasonable amount of time to resolve the issue before any public disclosure. We aim to release fixes for confirmed vulnerabilities within 90 days.

## Scope

This policy covers the code in this repository. Vulnerabilities in third-party dependencies should be reported to their respective maintainers, though we appreciate a heads-up if one affects this project.

Thank you for helping keep this project and its users safe.
